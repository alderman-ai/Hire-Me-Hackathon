# The alert: sequence and pipeline

The alert is a short LinkedIn campaign from Alex's own GetSales sender to the six Addvery stakeholders from his research. It says the hackathon is happening, why he's doing it, and that they can follow along. No names live in this folder. The six, their opening lines and the exact rendered text stay in git-ignored `live\`.

Status: draft until Alex ticks the pre-send gate. Copy: `copy.json`. Graph: `flow-nodes.json`, generated by `pipeline.py nodes`.

## Where it lives in GetSales

- Team: Alex's Team. Sender: Alex's own profile, alone (no rotation).
- A new automation folder (workspace) for the whole demo, which Alex can hide. The alert flow is the first flow in it; the ICP workflows join it later.
- Flow name: `Hackathon alert to the six`. Status `off` until the gate is ticked; started only then.

## Sequence

```
[1] Pre-check: already connected? (1 min)
 ├─ yes → [2] LinkedIn msg 1: {{custom_message_1}}          (at once)
 │          ↓ wait 1d
 │        [3] LinkedIn msg 2: why I'm doing this
 │          ↓ wait 3d
 │        [4] LinkedIn msg 3: last note
 │        → end
 └─ no  → [5] LinkedIn connect — note: the alert, under 200 characters (sends without note if LinkedIn limits notes)
            [6] Wait for acceptance (up to 10d, no automatic like)
             ├─ accepted → [7] LinkedIn msg 1: {{custom_message_1}}   (10 min after acceptance)
             │               ↓ wait 1d
             │             [8] LinkedIn msg 2: why I'm doing this
             │               ↓ wait 3d
             │             [9] LinkedIn msg 3: last note
             │             → end
             └─ 10 days, no answer → withdraw the request → end
```

Every message stops the sequence for that person the moment they reply. Messages go only inside the sender's LinkedIn window (Mon 07:45 to 16:30 Prague today, unless the flow gets its own window at the gate).

Changes from GetSales' standard "connect + 3 messages" template, and why:
- **Already connected → message 1 at once**, instead of ending. The alert has to reach everyone, not only new connections.
- **No automatic like** on their latest post while waiting. Six senior people at the company he's applying to: an automated like reads as a tactic.
- **Message 1 is only the variable** `custom_message_1`, exactly as Alex set it out: computed before import, imported as a lead field.

## `custom message 1`

One field per person, computed before import from what Alex's research already holds:

1. **Opening line:** one personal line, written from his research notes on that person (and rewritten by Alex at the gate if he chooses).
2. **The alert:** the fixed block in `copy.json` (`alert_block`).
3. **The notice line:** a link to the privacy notice, and the right to object in its own sentence (`privacy_line`).

## Pipeline, one file per stage

| Stage | What happens | Where |
| --- | --- | --- |
| 1. The six | Alex's list of six, with each profile URL | his research folder (read only) |
| 2. CSV | `live\alert.csv`, built from that list. No Sales Navigator export | `pipeline.py render` |
| 3. Enrichment | What his research already says about each person | his research folder (read only) |
| 4. `custom message 1` | Opening line + alert + notice line, per person | `live\six.json` → `pipeline.py render` |
| 5. Import | The six into the alert flow, `custom_message_1` as a lead field (GetSales inline enrolment, under 100 leads) | `live\enroll-leads.json` |
| 6. Start | The flow starts once Alex has ticked the gate | GetSales |

Each stage's wall-clock time goes into `..\live-run.md` with `pipeline.py stage "<stage>"`, for the clip.
